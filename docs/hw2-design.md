# Технические решения

Catalog-service объединяет каталог, заказы и авторизацию в одном Go-приложении. Общая PostgreSQL позволяет
резервировать товары и создавать заказ в одной транзакции. [C4-диаграмма](../README.md#целевая-архитектура)
описывает дальнейшее разделение сервисов.

OpenAPI 3.0 задаёт HTTP-интерфейс, DTO и ограничения входных данных. Версия oapi-codegen закреплена;
сгенерированный код исключён из Git и создаётся при сборке. Деньги передаются JSON-числами, внутри используются
decimal.Decimal и PostgreSQL NUMERIC(12,2). Проверка кратности копейке выполняется точно после декодирования:
числовая проверка multipleOf в kin-openapi использует float64 и ошибается на границах допустимых сумм.
Flyway применяет миграции до запуска приложения.

Заказ, позиции, остатки, использование промокода и история операций меняются атомарно. Блокировка строки
пользователя сериализует операции владельца; строки товаров блокируются в порядке ID, промокод — перед
изменением счётчика. Уникальный частичный индекс запрещает два активных заказа. Неуспешная операция
не влияет на ограничение частоты. Остаток хранится как BIGINT: возврат резерва после изменения складского
остатка может превысить INTEGER. Входное значение stock ограничено 2147483647.

JWT подписывается HS256 с проверкой issuer и claim типа токена. Access действует 20 минут, refresh — 14 дней.
Регистрация создаёт USER и SELLER; ADMIN создаётся при старте из конфигурации. Middleware проверяет доступ,
валидирует запросы и пишет JSON-лог с UUID запроса, маскируя пароли и токены.

## Правила расчёта и изменения заказа

- Процентная скидка свыше 70% не применяется: буквальная трактовка условия «в ином случае цена 100%».
  Суммы округляются до копеек half-up.
- При обновлении заказа цены фиксируются заново. Уже привязанный промокод не занимает второе использование;
  собственная квота учитывается при проверке лимита.
- Сумма ниже минимума снимает промокод и возвращает использование. Истёкший или выключенный промокод
  вызывает ошибку и откат обновления.
- Повторяющиеся product_id отклоняются до бизнес-логики. Отмена разрешена из CREATED и PAYMENT_PENDING.
- POST /orders/{id}/status доступен ADMIN и выполняет переходы обязательной цепочки состояний.
  ADMIN может изменять чужие заказы, сохраняя ограничения на состояние и остатки.
